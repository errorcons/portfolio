# Rhespaulin P. Manugas — Creative & Aesthetic Portfolio

A responsive, one-page student portfolio using plain HTML, CSS, and JavaScript. The design uses warm paper colors, sage green, terracotta accents, editorial typography, and illustrated project preview placeholders.

## Files
- `index.html` — portfolio content and page structure
- `style.css` — colors, layout, responsive design, and preview illustrations
- `script.js` — mobile navigation, active section highlighting, and current year
- `assets/images/` — add your actual project screenshots here

## Before publishing
1. Open `index.html`.
2. Replace `YOUR_EMAIL@example.com` with your professional email address in both the `mailto:` link and visible reminder/contact details.
3. Replace the illustrated Medicare and EcoQuest previews with real screenshots if available. The previews are design placeholders, not actual screenshots from your projects.
4. Add a short explanation of your own contribution to each project.
5. Add working project links if you have them.
6. Check all text and links.

## Test locally
- Double-click `index.html` to open it in a browser, or
- Open the folder in Visual Studio Code and use Microsoft's Live Preview extension.
- Test at phone width and click the mobile navigation links.

## Publish for free with GitHub Pages
1. Sign in at https://github.com and create a **public** repository named `portfolio`.
2. Choose **Add file → Upload files** and upload the contents of this folder, not the ZIP itself. Keep `index.html`, `style.css`, `script.js`, and `assets` at the repository root.
3. Commit the files.
4. Open **Settings → Pages**.
5. Under Build and deployment, choose **Deploy from a branch**.
6. Select branch `main` and folder `/(root)`, then click **Save**.
7. Wait for publishing. Open the public link displayed in Settings → Pages. It will usually look like `https://YOUR-USERNAME.github.io/portfolio/`.
8. Test the live link in a private/incognito window and on a phone.

## Updating
Edit the files, upload the changes to the same repository, commit, and wait for GitHub Pages to redeploy.

Only publish information you are comfortable making public. Do not upload passwords, API keys, or private documents.
